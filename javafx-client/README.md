# JavaFX-клиент «Теремок»

Основной клиент проекта. Вся клиентская логика находится в этом модуле;
консольный клиент больше не развивается. Общий backend-client-shared содержит
только контракты REST, а не клиентские сервисы.

## Запуск

Нужны Java 21 и запущенный Docker Desktop. Maven скачивается wrapper-скриптом.
Из корня репозитория:

```powershell
docker compose up --build -d
.\mvnw.cmd install -DskipTests
.\mvnw.cmd -pl javafx-client javafx:run
```

Linux/macOS используют `./mvnw` вместо `.\mvnw.cmd`.
В IntelliJ IDEA открыть корневой pom.xml, выбрать JDK 21 и Maven-проект.
Для первого запуска GUI нужны зависимости backend-client-shared:
сначала выполнить install, затем javafx:run только для javafx-client.
Можно использовать готовый `javafx-client/run.ps1`.

Адрес по умолчанию — http://localhost:8080. Он редактируется на экране входа,
также поддерживается BACKEND_URL или свойство teremok.api. JDBC-драйвера,
реквизитов PostgreSQL/MinIO и SQL в клиенте нет.

## Сценарии

- Регистрация сразу открывает аккаунт. JWT хранится только в памяти; выход очищает
  сеанс. При перезапуске нужен новый вход. Срок JWT — семь дней.
- Каталог: поиск по названию, фильтры языка/оригинала-перевода, сортировка
  заголовками столбцов. Двойное нажатие открывает запись роли.
- Запись роли: выбор роли и фрагмента, запись WAV с микрофона (максимум 120 секунд)
  либо загрузка готового аудио до 100 МБ. Вариантов может быть много.
  При недоступности микрофона можно загрузить готовый файл.
- В каждом фрагменте явно выбрать один вариант, затем опубликовать всю роль.
  Выбранные исходники переходят в опубликованное хранилище; остальные сохраняются.
- Сборка: выбрать одну опубликованную озвучку каждой роли, в том числе другого
  пользователя. Результат — один MP3 или отдельные MP3 по сегментам.
  Пока окно открыто, статус проверяется автоматически; готовые файлы можно слушать
  или сохранять. Закрытие окна не отменяет уже отправленное задание рендера.
- Статистика показывает обработанные сущности: пользователей, произведения,
  черновики, опубликованные роли и готовые сборки. Это не число сообщений Kafka:
  повторная доставка события не должна увеличивать число пользователей.
- Excel: чекбоксы пяти сервисов, FileChooser для пути, XLSX с листами таблиц.
  Export API выполняет JDBC-выгрузку на backend, клиент только скачивает файл.
  Renderer не имеет собственной БД и потому не предлагается отдельным чекбоксом.

Ключевые окна — FXML, оформление — app.css. Контроллеры отвечают за UI,
RestApi — за HTTP и сеанс, AudioService — за локальные аудиоустройства.
REST, загрузки и экспорт выполняются в фоновых задачах.

Это согласованный учебный REST-вариант: прямой JDBC, полный CRUD и экспорт только
отфильтрованной таблицы из буквального задания КР №2 намеренно не реализованы.
Общий SQL-экспорт доступен любому вошедшему пользователю локального учебного стенда
и содержит все колонки выбранных таблиц, включая хэши паролей. Это не модель прав
для промышленного приложения.
