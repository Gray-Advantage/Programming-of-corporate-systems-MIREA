# Веб-клиент «Теремок»

Svelte 5, SvelteKit 2, TypeScript, собственные компоненты и CSS. Русский интерфейс
для ПК, светлая тема с зелёным акцентом. Веб-клиент добавлен рядом с JavaFX.

## Запуск всего проекта в Docker

Из корня репозитория:

```powershell
Copy-Item .env.example .env
# Указать свой временный пароль администратора в .env.
docker compose -f compose.yaml -f compose.web.yaml up -d --build
node scripts/seed-library.mjs
```

Если `.env` уже существует, не перезаписывайте его. В текущем рабочем каталоге
он подготовлен; логин — `BOOTSTRAP_ADMIN_LOGIN`, пароль — `BOOTSTRAP_ADMIN_PASSWORD`.
Пароль не включается в Git. Создание bootstrap-администратора выполняется только
при отсутствии такого логина. При первом входе требуется сменить временный пароль.

Открыть http://localhost:5173. API по-прежнему доступен через http://localhost:8080.
Скрипт seed публикует три исходных произведения из `examples/`; новые события
появляются в каталогах асинхронно. Загрузка примеров повторяема, но повторно
публиковать их во время параллельного редактирования не следует.

Обычный `docker compose down` не удаляет данные. Для остановки всего стенда:

```powershell
docker compose -f compose.yaml -f compose.web.yaml down
```

## Разработка без контейнера frontend

Требуется Node.js 22.12 или новее. Backend запускается обычным `docker compose up -d`.
Не запускайте контейнер `web-client` одновременно с dev-сервером на том же порту.

```powershell
cd web-client
npm ci
npm run dev
```

По умолчанию SvelteKit проксирует запросы на `http://127.0.0.1:8080`.
Для другого адреса задайте `BACKEND_URL` в `web-client/.env`.
Проверка и production-сборка: `npm run check`, `npm run build`.
Production без Docker: `BODY_SIZE_LIMIT=105M`, `PORT=5173`, затем `node build`.
При размещении за внешним reverse proxy задайте корректный `ORIGIN`.

## Возможности

- Вход, регистрация, сохраняемая сессия, смена пароля и выход.
- Сетка произведений, поиск, фильтры, серверные сортировка и пагинация.
- Создание и изменение карточек, контроль версии, архив и восстановление.
- Массовые архивирование/восстановление, изменение статуса и тегов.
- Коллекции, теги, заметки с автором, временем и закреплением.
- Запись WAV с микрофона до 120 секунд либо загрузка аудио до 100 МБ;
  несколько дублей, прослушивание, выбор и публикация полной роли.
- Выбор опубликованной озвучки каждой роли, сборка MP3 целиком или по частям,
  опрос статуса, прослушивание, скачивание и история собственных сборок.
- Экспорт текущего фильтра в CSV со всеми полями произведений.
- Импорт CSV выполняется консольным TextWorkDeployer, без веб-формы импорта.
- Аналитика библиотеки и прежняя статистика backend, Excel по выбранным сервисам.
- Администрирование пользователей, справочник коллекций, аудит и Swagger.

Читатель просматривает библиотеку и экспортирует каталог в CSV. Редактор также
управляет произведениями, заметками и озвучкой. Администратор управляет пользователями,
коллекциями, смотрит аудит и может окончательно удалить архивную карточку.
Выгрузка Excel всех таблиц со всеми полями доступна всем авторизованным ролям.
Таблицы журнала аудита включаются только для администратора (прямое требование КР №3).
Поля длиннее лимита Excel сохраняются полностью в колонках-продолжениях [2], [3].

Изменение сценария уже созданных ролей ограничено: его UUID и связи с записями
сохраняются. Метаданные редактируются обычным образом. Для другого текста нужно
создать новое произведение; к пустой карточке сценарий можно добавить позднее.

## Устройство клиента

`src/routes/(app)` — основные страницы. `src/lib/components` — библиотека,
обложки, запись, заметки и состояние рендера. `src/lib/audio.ts` преобразует
запись браузера в mono WAV PCM16. `src/lib/server/proxy.ts` — серверный прокси
к существующему Java API.

Access- и refresh-токены хранятся в HttpOnly/SameSite cookies. JavaScript получает
только профиль пользователя. Прокси автоматически обновляет access-токен и
проверяет Origin у изменяющих запросов. При HTTPS cookies становятся Secure.
Сеансы хранятся в PostgreSQL; рестарт web-контейнера не требует повторного входа.

Шрифт Golos Text хранится локально в зависимостях. Иконки — Hugeicons;
обложки типографические, без изображений, созданных генеративной моделью.

## Проверки

```powershell
# Из корня, при работающем стенде и подготовленном .env:
node scripts/verify-web-stack.mjs
node scripts/verify-web-proxy.mjs
.\mvnw.cmd -pl backend/auth-service,backend/catalog-service,backend/recordings-service,backend/draft-recordings-service,backend/text-work-content-service,backend/database-exporter,javafx-client -am test
```

Сквозной тест создаёт собственных пользователей и произведения, проверяет настоящие
PostgreSQL, Kafka, MinIO и FFmpeg. Если bootstrap-пароль ещё временный, тест меняет
его и обновляет локальный `.env`; повторно раскрывать пароль в выводе он не будет.
Отчёт — `artifacts/web-verification.json`, тестовый WAV — `artifacts/voice.wav`.
Проверку прокси запускайте после основной: она использует собственную CSV-запись
из отчёта, проверяет окончательное удаление и сохраняет `artifacts/proxy-verification.json`.
Результаты и ручные ограничения описаны в `docs/web-verification.md`.
