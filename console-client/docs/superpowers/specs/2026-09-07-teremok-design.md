# Teremok — озвучивание книг по ролям

Дата: 2026-09-07
Статус: спецификация утверждена, реализация не начата

## 1. Что это

Консольное приложение на Java. Пользователь берёт встроенную книгу, записывает
голосом реплики выбранного персонажа и публикует получившуюся роль. Другие
пользователи собирают свой вариант книги из ролей разных авторов, слушают его и
голосуют за понравившиеся озвучки. Роли с лучшим рейтингом предлагаются первыми.

Приложение работает без сети: все пользователи — это профили на одной машине,
общее хранилище лежит на диске.

## 2. Термины

| Термин | Значение |
| --- | --- |
| Книга | Встроенный текст, размеченный по говорящим |
| Реплика (Line) | Одна строка книги: номер, говорящий, текст |
| Персонаж (Speaker) | Говорящий в книге. В коде `Speaker`, потому что `Character` занят `java.lang` |
| Роль (Voicing) | Озвучка одного персонажа одним автором — единица публикации и голосования |
| Каст (Cast) | Раскладка «персонаж → выбранная роль» на один сеанс прослушивания |
| Профиль | Пользователь приложения |

## 3. Функциональные требования

### 3.1 Профили

- При старте приложение показывает список профилей и пункт «создать новый».
- Профиль — только имя, без пароля. Имя: от 1 до 24 символов, буквы, цифры,
  дефис и подчёркивание; пробелы запрещены.
- `profileId` — имя в нижнем регистре. Имена, совпадающие без учёта регистра,
  считаются одним профилем; создать второй такой нельзя.
- Профиль можно сменить из главного меню. Удаления профилей нет.

### 3.2 Главное меню

```
1  Слушать книгу
2  Озвучить книгу
3  Мои озвучки
4  Сменить профиль
0  Выход
```

### 3.3 Прослушивание

1. Пользователь выбирает книгу из списка.
2. Приложение строит каст автоматически: каждому персонажу назначается
   опубликованная роль с наибольшим рейтингом. Персонаж без опубликованных
   ролей помечается «— текстом —».
3. Экран каста показывает персонажей, назначенных авторов и их рейтинг. Можно
   сменить голос любому персонажу или начать прослушивание.
4. Экран выбора голоса показывает опубликованные роли этого персонажа,
   отсортированные по рейтингу, с числом лайков и дизлайков и собственным
   голосом пользователя. Отсюда же ставятся и снимаются оценки. Дополнительный
   пункт «— читать текстом —» доступен всегда.
5. Прослушивание идёт по репликам подряд. Перед каждой печатается строка вида
   `[Волк · masha] Куда ты идёшь?`. Если аудио есть — играет WAV; если нет —
   выдерживается пауза для чтения.
6. Между репликами проверяется наличие ввода. Нажатие Enter останавливает
   воспроизведение и возвращает в экран каста.

Собственные черновики пользователя в автоматический каст не попадают: каст
собирается только из опубликованных ролей.

### 3.4 Запись роли

1. Пользователь выбирает книгу, затем персонажа. У каждого персонажа виден
   прогресс собственной роли: `не начато` или `7/20`.
2. Запись идёт по репликам этого персонажа, начиная с первой незаписанной.
3. Экран реплики показывает номер, текст и приглашение начать. Первый Enter
   запускает запись, второй останавливает.
4. После остановки доступны: прослушать, перезаписать, перейти к следующей,
   выйти. Уже записанные реплики пропускаются при повторном входе.
5. Из экрана реплики доступен список всех реплик персонажа с отметками о
   записи. Выбор номера в этом списке переводит запись на нужную реплику, что
   позволяет перезаписать любую уже готовую.
6. Каждая записанная реплика немедленно сохраняется на диск. Выход в любой
   момент оставляет корректный черновик.

Ограничение: один автор может иметь не более одной роли на персонажа в книге.
Повторная озвучка того же персонажа — это перезапись существующей роли.

### 3.5 Мои озвучки

Список ролей текущего профиля: книга, персонаж, статус, прогресс, рейтинг.
Действия:

- продолжить запись;
- прослушать роль целиком: собственный персонаж звучит из этой роли, даже если
  она ещё черновик; остальные персонажи берутся из автоматического каста;
- опубликовать — доступно только при прогрессе 100 % и хотя бы одной реплике;
- снять с публикации — роль исчезает из чужих кастов, голоса сохраняются и
  возвращаются вместе с ролью при повторной публикации;
- удалить — удаляется папка роли вместе с аудио и голосами, действие требует
  подтверждения.

### 3.6 Голосование и рейтинг

- Рейтинг роли = число лайков минус число дизлайков.
- Сортировка: по рейтингу по убыванию; при равенстве выше роль с большим числом
  лайков; при равенстве — более поздняя по дате создания; при равенстве —
  по `voicingId` по алфавиту. Порядок полностью детерминирован.
- Один профиль — один голос на роль. Повторная подача того же голоса снимает
  его. Подача противоположного — заменяет.
- Голосовать можно только за опубликованные роли.
- Голосовать за собственную роль нельзя: попытка отклоняется с пояснением.

## 4. Доменная модель

```
Book      id, title, List<Line>
Line      number, speakerId, text
Speaker   id, name                     // выводится из реплик, отдельно не хранится
Profile   id, name
Voicing   id, bookId, speakerId, authorId, status, createdAt, Set<Integer> recordedLines
Vote      voicingId, profileId, VoteKind (LIKE | DISLIKE)
Cast      Map<speakerId, voicingId>    // отсутствие ключа = читать текстом
VoicingStatus  DRAFT | PUBLISHED
```

Доменные объекты неизменяемы и не знают ни про файлы, ни про звук, ни про
консоль.

Идентификаторы:

- `bookId` — имя файла ресурса без расширения (`shapochka`);
- `speakerId` — имя персонажа в нижнем регистре, пробелы заменены дефисами
  (`красная-шапочка`);
- `profileId` — имя профиля в нижнем регистре;
- `voicingId` — `bookId + "__" + speakerId + "__" + authorId`.

## 5. Формат книги

Книги — текстовые ресурсы в UTF-8, лежат в `src/main/resources/books/`. В
рантайме книги не добавляются и не редактируются.

```
title: Красная Шапочка
---
Рассказчик: Жила-была маленькая девочка.
Волк: Куда ты идёшь, Красная Шапочка?
Шапочка: К бабушке, несу пирожки.
```

Правила разбора:

- заголовок до строки `---` содержит пары `ключ: значение`; обязателен `title`;
- после `---` каждая непустая строка — реплика вида `Имя: текст`;
- пустые строки игнорируются;
- строка без двоеточия — ошибка разбора с указанием номера строки;
- реплики нумеруются подряд с 1 в порядке следования; номер стабилен и служит
  именем файла аудио;
- рассказчик — обычный персонаж и может быть озвучен;
- список персонажей строится из реплик в порядке первого появления;
- максимум 9999 реплик в книге.

Текст книги считается неизменяемым после выпуска: номера реплик привязаны к
нему. Изменение текста требует нового `bookId`.

В комплект входят три коротких народных сказки, написанные для проекта своими
словами: «Красная Шапочка», «Теремок», «Колобок».

## 6. Хранилище

```
data/
  profiles.txt
  voicings/
    shapochka__волк__sergey/
      meta.txt
      votes.txt
      line-0002.wav
      line-0007.wav
```

`profiles.txt` — по строке на профиль, `id=Отображаемое имя`.

`meta.txt`:

```
book=shapochka
speaker=волк
author=sergey
status=PUBLISHED
created=2026-09-07T12:34:56Z
```

`votes.txt` — по строке на голос, `profileId=LIKE` или `profileId=DISLIKE`.
Файл отсутствует, если голосов нет.

Аудио: `line-%04d.wav`, номер — номер реплики в книге.

Прогресс роли считается по фактически существующим непустым файлам среди реплик
персонажа. Пропавший или пустой файл делает роль неполной.

Все записи атомарны: данные пишутся во временный файл `<имя>.tmp` рядом, затем
переносятся через `Files.move` с `ATOMIC_MOVE`. Оставшиеся `.tmp` удаляются при
следующем открытии роли.

Каталог `data/` создаётся в рабочей директории процесса при первом запуске. При
`./gradlew run` это корень проекта.

Приложение рассчитано на один запущенный экземпляр: блокировок нет, две
одновременные копии могут испортить общие файлы.

## 7. Аудио

Формат записи: PCM signed, 16 000 Гц, 16 бит, моно, little-endian. Контейнер —
WAV.

Запись: `TargetDataLine` открывается на этом формате, `AudioSystem.write`
пишет поток в файл в фоновом потоке, главный поток ждёт Enter и закрывает
линию. Длительность одной реплики ограничена 120 секундами; по достижении
лимита запись останавливается сама с сообщением.

Воспроизведение: `Clip` с ожиданием окончания в цикле и проверкой ввода, чтобы
Enter прерывал.

Пауза для реплики, читаемой текстом: `max(1.2 с, 0.06 с × число символов)`, но
не больше 8 секунд.

Железо скрыто за интерфейсами:

```java
interface AudioRecorder {
    boolean isAvailable();
    RecordingSession start(Path target);   // RecordingSession.stop() завершает запись
}

interface AudioPlayer {
    boolean isAvailable();
    void play(Path file);
}
```

Кодировка UTF-8 задаётся явно для чтения и записи всех файлов, а также для
`System.out` и `System.in`, иначе русский текст ломается на Windows.

## 8. Обработка ошибок

| Ситуация | Поведение |
| --- | --- |
| Микрофон недоступен | Сообщение и возврат в меню; черновик не изменяется |
| Устройство вывода недоступно | Сообщение; прослушивание работает в текстовом режиме |
| Файл реплики пропал или пуст | Реплика читается текстом с пометкой; роль считается неполной |
| Повреждён `meta.txt` роли | Роль пропускается с предупреждением, остальные читаются |
| Повреждена строка в `votes.txt` | Строка пропускается, остальные голоса учитываются |
| Ошибка разбора книги | Книга не попадает в список, выводится причина с номером строки |
| Нет прав на запись в `data/` | Сообщение и завершение работы: без диска работать нечем |
| Некорректный ввод в меню | Повтор приглашения; исключения наружу не выбрасываются |

Исключения не показываются пользователю в сыром виде: каждое сообщение
объясняет, что произошло и что делать.

## 9. Структура кода

```
src/main/java/space/grayt/teremok/
  Main.java
  domain/     Book Line Speaker Profile Voicing Vote Cast VoicingStatus VoteKind
  book/       BookLibrary BookParser
  storage/    VoicingRepository ProfileRepository
              FileVoicingRepository FileProfileRepository AtomicTextFile
  audio/      AudioRecorder AudioPlayer RecordingSession
              JavaSoundRecorder JavaSoundPlayer
  app/        VoicingService VotingService CastBuilder PlaybackService
  cli/        Console MainMenu ListenFlow CastScreen RecordFlow MyVoicingsScreen
src/main/resources/books/
  shapochka.txt teremok.txt kolobok.txt
```

Зависимости направлены строго в одну сторону: `cli → app → storage, audio,
book → domain`. Домен не зависит ни от чего.

В рантайме зависимостей нет — только JDK.

## 10. Тестирование

Реализация ведётся через тесты. JUnit 5 подключается только как тестовая
зависимость. Аудио в тестах подменяется фейками: «запись» создаёт файл-заглушку,
«воспроизведение» отрабатывает мгновенно и запоминает, что играло.

Обязательное покрытие:

- разбор книги: корректный текст, пустые строки, строка без двоеточия,
  отсутствие `title`, повторное появление персонажа;
- прогресс роли: частичная запись, пропавший файл, пустой файл;
- рейтинг: подсчёт, сортировка, все тай-брейки, смена голоса, снятие голоса,
  запрет голосовать за себя, запрет голосовать за черновик;
- построение каста: выбор лучших, персонаж без ролей, снятая с публикации роль
  исключается, чужие черновики исключаются;
- репозитории: сохранение и чтение во временной директории, атомарность записи,
  повреждённый `meta.txt` не ломает чтение остальных ролей;
- воспроизведение: правильная последовательность аудио и текстовых реплик;
- сквозной сценарий на подставных потоках ввода-вывода: создание профиля →
  запись двух реплик → выход → возврат → дозапись → публикация → голос от
  второго профиля → изменение порядка в списке.

## 11. Сборка и запуск

- JDK: Temurin 21, устанавливается отдельно (`brew install --cask temurin@21`).
- Gradle с wrapper, плагин `application`, `options.release = 21`.
- Запуск: `./gradlew run`. Тесты: `./gradlew test`.

## 12. Вне области

Не делаем: сеть и клиент-сервер, MP3 и любые форматы кроме WAV, синтез речи,
добавление и редактирование книг в рантайме, пароли и разграничение доступа,
монтаж и обработка звука, регулировка громкости, несколько версий одной роли от
одного автора, одновременная работа нескольких экземпляров приложения.

## 13. Известные ограничения

- Номера реплик привязаны к тексту книги; правка текста ломает существующие
  озвучки, поэтому текст выпущенной книги неизменяем.
- Рейтинг «лайки минус дизлайки» не учитывает число голосов: роль с одним
  лайком стоит выше роли с нулевым балансом при сотне голосов.
- Общее хранилище не защищено от одновременной записи двумя экземплярами.
- Построение списка ролей сканирует каталог целиком. На домашних объёмах это
  незаметно, на десятках тысяч ролей потребуется индекс.
