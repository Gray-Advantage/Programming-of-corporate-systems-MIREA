# Console client

Нативное консольное приложение на Java 21. Оно не входит в Docker Compose, чтобы
микрофон и звук одинаково работали на Windows и macOS. Все данные — профили,
произведения, озвучки, записи фрагментов и голоса — хранятся в PostgreSQL, сами
WAV-файлы лежат на диске.

## Запуск

Все команды выполняются из корня репозитория.

1. Скопируйте настройки и при необходимости поправьте их:

   ```shell
   cp .env.example .env
   ```

   Если на машине уже работает другой PostgreSQL на порту 5432, поставьте в `.env`
   другой порт, например `POSTGRES_PORT=5433`.

2. Запустите базу данных:

   ```shell
   docker compose up -d postgres
   ```

   При первом запуске контейнер создаёт таблицы из `database/schema.sql` и заполняет
   их демонстрационными данными из `database/seed.sql`: три сказки, шесть профилей,
   16 озвучек, записи и голоса. Проверить:

   ```shell
   docker compose exec -T postgres psql -U teremok -d teremok -c 'select count(*) from voicings'
   ```

3. Запустите клиент:

   ```shell
   ./gradlew :console-client:run
   ```

   ```powershell
   .\gradlew.bat :console-client:run
   ```

   Или через Maven — `pom.xml` лежит рядом с `build.gradle.kts` и собирает те же
   исходники. Устанавливать Maven не нужно: `mvnw` сам скачает Maven 3.9 при первом
   запуске. Команды — из папки `console-client`:

   ```shell
   cd console-client
   ./mvnw -q exec:java    # запустить клиент
   ./mvnw test            # прогнать тесты
   ```

   ```powershell
   cd console-client
   .\mvnw.cmd -q exec:java
   ```

Клиент берёт настройки из переменных окружения, а если переменной нет — из
ближайшего файла `.env` (в рабочей папке или до трёх папок выше, поэтому
`./gradlew :console-client:run` находит `.env` в корне репозитория):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `POSTGRES_HOST` | `localhost` | адрес PostgreSQL |
| `POSTGRES_PORT` | `5432` | порт PostgreSQL |
| `POSTGRES_DB` | `teremok` | имя базы |
| `POSTGRES_USER` | `teremok` | пользователь |
| `POSTGRES_PASSWORD` | `teremok` | пароль |
| `DB_URL` | — | полный JDBC URL, заменяет пять настроек выше |
| `AUDIO_DIR` | `data/audio` | папка с WAV-файлами |
| `TEXT_WORKS_SOURCE` | `database` | `backend` — брать произведения из backend |

Если база недоступна, клиент выводит адрес, к которому пытался подключиться, и
подсказку `docker compose up -d postgres`, после чего завершается.

## Сброс базы

Чтобы вернуть демонстрационные данные, пересоздайте только том PostgreSQL:

```shell
docker compose rm -sf postgres
docker volume rm teremok_postgres-data
docker compose up -d postgres
```

Не используйте для этого `docker compose down --volumes`: команда удаляет и том
Kafka.

## Аудио

Записи хранятся в `console-client/data/audio/<id озвучки>/fragment-NNNN.wav` (папка
`data/audio` считается от рабочей папки клиента; другую задаёт `AUDIO_DIR`). Формат —
WAV, 16 кГц, 16 бит, моно. В таблице `voicing_recordings` хранится путь относительно
этой папки, например `1/fragment-0001.wav`, и длительность записи. Строка появляется
только после того, как файл записан на диск; удаление озвучки удаляет и её папку.
Если файла нет, фрагмент при прослушивании читается текстом.

Папка `data/` не хранится в git, поэтому WAV-файлы демонстрационных данных в
репозиторий не входят: без них сказки читаются текстом.

## Устройство

Слои: консольные экраны (`cli`) → сервисы с бизнес-правилами (`app`) → репозитории на
JDBC (`storage`, `textwork`) → PostgreSQL. SQL есть только в репозиториях, все запросы
параметризованы. «Опубликовать все готовые» в «Моих озвучках» выполняется одной
транзакцией: публикуются либо все готовые черновики, либо ни один.

Статусы озвучки: черновик → опубликовано ⇄ снято с публикации. Опубликовать можно
только роль, у которой записаны все фрагменты; удалить — только черновик или снятую с
публикации роль; голосовать можно только за опубликованные чужие озвучки.

## Произведения из backend

С `TEXT_WORKS_SOURCE=backend` список произведений загружается из `CatalogService`, а
сегменты, фрагменты и роли — из `TextWorkContentService`. Для этого должен быть
запущен Docker-стенд backend (см. корневой README); клиент ходит к Traefik по адресу
`http://localhost:8080`, другой адрес задаётся переменной `BACKEND_URL`. Озвучки
по-прежнему хранятся в PostgreSQL, поэтому озвучить можно только произведения,
которые есть и в базе.

В коде клиента произведение представлено как `TextWork`, роль — как `VoicePart`, а
минимальная часть текста для записи — как `TextWorkFragment`.
