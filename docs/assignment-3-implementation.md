# Соответствие КР №3

Оригинал: `docs/assignment-3.txt`. Предметная область не менялась: основная сущность
— произведение для озвучивания, справочная — коллекция библиотеки. Имена Student Hub
в прикладной модели не используются. JavaFX остаётся отдельным клиентом.

## Пути API

Условные `items` из задания заменены на `library/works`, `references` — на
`library/collections`. Остальные пути сохраняют назначение. Авторизация web-клиента:
`/api/v1/session/login`, `/register`, `/refresh`, `/logout`, `/me`, `/password`.
Старые `/api/v1/auth/login` и `/register` сохранены для клиентов прежней версии.

Существующие Kafka-проекции каталога и содержимого сохранены. При создании карточки
или изменении её метаданных событие записывается в transactional outbox и отправляется
в `text-work-added` с повтором при ошибке. Идентификаторы существующего сценария
при редактировании не меняются. Tombstone не позволяет повторному событию
восстановить окончательно удалённую карточку.

Аудит физически разделён по владельцам БД: входы/пользователи в auth, произведения/
заметки/коллекции в catalog. В интерфейсе это два раздела одного журнала.
Выгрузка Excel всех таблиц со всеми полями доступна каждой авторизованной роли.
Только таблицы auth_audit и library_audit исключаются из выгрузки неадминистратора,
так как раздел 11 задания ограничивает просмотр аудита. Для администратора они включены.
CSV также содержит все поля произведения. Импорт CSV выполняется только консольным
TextWorkDeployer: preview и apply остаются отдельными backend REST-запросами,
а через SvelteKit-прокси импорт недоступен.

Клиентская часть не подключается к JDBC и MinIO напрямую. Для будущего Android-клиента
используется тот же Java REST API, без зависимости от SvelteKit-прокси.
