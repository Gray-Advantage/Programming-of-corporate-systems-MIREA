# Проверка веб-клиента и КР №3

Дата: 31 октября 2026. Рабочий каталог: `Programming-of-corporate-systems-MIREA`.
Проверялись настоящие Docker-контейнеры с PostgreSQL, Kafka, MinIO и FFmpeg,
а не моковые ответы. Веб-клиент собран с Svelte 5.57.3 / SvelteKit 2.70.3.

## Автоматические проверки

- `npm run check`: **0 ошибок, 0 предупреждений**.
- `npm run build`: production-сборка успешна; также успешно собран Docker-образ.
- Maven `test` по auth, catalog, draft-recordings, recordings, content, exporter
  и JavaFX с зависимостями: **14 тестов, 0 ошибок, 0 падений**; JavaFX компилируется.
- `git diff --check`: ошибок пробелов нет.
- Docker healthcheck: PostgreSQL, Kafka, MinIO, auth, catalog, draft-recordings,
  recordings, content и web-клиент healthy. Renderer и export-api запущены;
  их работа дополнительно проверена реальными запросами рендера и выгрузки.
- Flyway: в catalog успешно применены V1 (библиотека), V2 (tombstone удаления),
  V3 (признак оригинала/перевода); остальные сервисы применяют собственные миграции.

`node scripts/verify-web-stack.mjs`:

- JWT на 15 минут, refresh-ротация, отказ повторно использованному и отозванному
  refresh-токену, обязательная смена временного пароля.
- Различия reader/editor/admin, отказ в изменении читателю, отказ в просмотре
  пользователей и аудита, немедленная блокировка отключённой учётной записи.
- Валидация 400, уникальность кода и конфликт версии 409, CRUD, поиск/фильтры,
  серверная пагинация/сортировка, заметки, архив и восстановление.
- Массовая операция с отдельным успехом и ошибкой для неизвестного UUID.
- CSV: неправильная строка, preview без изменения данных, apply, защита повторного
  применения, экспорт по фильтру. Аналитика, аудит, OpenAPI и настоящий XLSX.
- Настоящий WAV: загрузка, скачивание, публикация всех ролей через Kafka,
  сборка FFmpeg в режимах SINGLE_FILE и BY_SEGMENTS, скачивание MP3,
  история сборок и отзыв сеанса при выходе.

`node scripts/verify-web-proxy.mjs` (после основного теста):

- Cookies HttpOnly / SameSite=Lax; токены не попадают в JSON ответа веб-входа.
- Изменяющий запрос с чужим Origin получает 403.
- Три параллельных запроса проходят с одной ротацией refresh-токена.
- Все шесть спецификаций OpenAPI доступны через web-прокси.
- Окончательное удаление собственного тестового CSV-произведения администратором:
  после удаления GET возвращает 404.
- Шестая неудачная попытка входа получает 429.
- Выход очищает обе cookies.

Дополнительно проверено: multipart WAV проходит через SvelteKit-прокси с HTTP 201;
Swagger перенаправляет в каталог своих ресурсов, загружает интерфейс и использует
публичный `http://localhost:5173` вместо внутреннего `http://traefik`.
Запросы из документации по исходным путям `/api/v1/*` проходят через тот же прокси.

## Что проверить вручную

**Настоящий микрофон.** Код записи включён, WAV-преобразование реализовано,
но доступ к физическому микрофону и качество конкретного устройства автоматически
не проверялись. В Edge откройте запись роли, разрешите доступ к микрофону,
запишите реплику, остановите запись и прослушайте сохранённый дубль.

**Системный диалог загрузки файла в Edge.** Автоматизация расширения потребовала
`Allow access to file URLs`; разрешения браузера не менялись. Поэтому прохождение
самого системного диалога не подтверждено автоматикой. Серверная загрузка WAV и
multipart-передача через web-прокси проверены отдельно, а загруженные дубли проверены
и воспроизведены в интерфейсе.

Это ограничения проверки оборудования и браузерной автоматизации, а не заглушки
в интерфейсе. Остальные перечисленные результаты получены выполненными проверками.
