# Общие ошибки и сервисный слой

Оба пункта КР №3 реализованы: единый JSON ошибок и перенос прикладной логики из
HTTP-контроллеров в сервисы. Проверка выполнена 31.10.2026.

## Контракт ошибок

Модуль `backend/backend-shared/http-api` подключён к auth, catalog, draft-recordings,
recordings, text-work-content и HTTP-режиму database-exporter. Автоконфигурация
регистрирует обработчик исключений MVC, фильтр Correlation ID и `/error` для
ошибок servlet-контейнера. Security-фильтры используют тот же `ApiErrors`.

```json
{
  "status": 409,
  "code": "conflict",
  "message": "Данные изменились или запись уже существует. Обновите страницу",
  "correlationId": "a79a811d-4174-4d9a-80eb-f1d633449366"
}
```

Ответ имеет `Content-Type: application/json`; HTTP-статус совпадает с `status`.
Тот же идентификатор возвращается в `X-Correlation-ID`. Входящий идентификатор
принимается только в формате `[a-zA-Z0-9-]{1,64}`, иначе создаётся UUID. При обращении
к auth из других сервисов идентификатор передаётся дальше.

Обработаны ошибки валидации и JSON, параметры неправильного типа, отсутствующие
файлы/multipart, неизвестные адреса, неподдерживаемые методы и форматы, отсутствие
авторизации, недостаток прав, конфликты БД/версий, превышение размера файла и
внутренние сбои. Внутренние исключения и SQL остаются в серверных логах; клиент
получает безопасное сообщение. Недоступность auth возвращает 503.

Существующие доменные коды (`invalid_credentials`, `invalid_draft`,
`invalid_recording_selection` и другие) сохранены. Поля `message` и `code`
совместимы с прежними клиентами. Локальные ошибки SvelteKit-прокси имеют такой же
формат; ошибки Java API проксируются вместе с Correlation ID.

Ошибки отдельных строк CSV и отдельных книг массовой операции остаются в
результате соответствующей операции (`errors` рядом с `success` или счётчиками).
Это успешный HTTP-ответ с результатами обработки, а не ошибка всего запроса.

## Границы слоёв

| Сервис | Прикладная логика |
| --- | --- |
| Auth | `IdentityService`: регистрация вместе с первым сеансом, прежний API токенов, вход/выход, пользователи, поиск и аудит |
| Catalog | `LibraryService`: изменения произведений; `LibraryManagementService`: список, сортировка, страницы, массовые операции, коллекции, заметки, аналитика, аудит; `CatalogQueryService`: прежний каталог |
| Content | `TextWorkContentQueryService`: поиск, подсчёт и преобразование содержимого в DTO |
| Draft | `DraftRecordingService`: проверка владельца, загрузка, открытие аудиофайла, публикация и удаление |
| Recordings | `RecordingService`: создание и история сборок; `RecordingFilesService`: владелец, готовность, индекс файла и открытие хранилища |
| Export | `ExportService`: выбор БД, политика выгрузки, временный файл, Excel и статистика |

Контроллеры принимают HTTP-параметры, выполняют Bean Validation DTO, извлекают
идентичность пользователя, вызывают сервис и оформляют HTTP-ответ. В них нет SQL,
репозиториев, `JdbcTemplate`, `ObjectStorage` или управления транзакциями.
Входные DTO библиотеки вынесены из контроллера в `LibraryRequests`.

Изменения заметок/коллекций и их аудит выполняются в общей транзакции. При правке
или удалении заметка блокируется `FOR UPDATE` до проверки автора. Изменение
коллекции теперь также записывается в аудит. Ограничения ролей для изменений
произведений, заметок и коллекций проверяются сервисом при непосредственном вызове,
а не только HTTP-фильтром.

Каждая книга массовой операции обрабатывается в отдельной транзакции
`REQUIRES_NEW`: неуспешная запись откатывается, остальные сохраняются. Читающие
запросы работают в транзакциях `readOnly`. Успешный вход и создание refresh-сеанса
атомарны; счётчик и аудит отклонённого входа сохраняются при отказе авторизации.

## Проверка

- `ApiErrorsTest`: единая схема и заголовок, HTTP 400/401/403/404/405/409/413/415/429/500/503,
  ошибки MVC и фильтров, отсутствие внутренних подробностей.
- `LibraryTransactionsTest`: реальная H2 и Spring-транзакции; откат вставки/правки
  коллекции, создания/правки/удаления заметки, права автора и частичный успех bulk.
- `RecordingFilesServiceTest`: хранилище не открывается до проверки владельца,
  готовности сборки и границ индекса.
- `scripts/verify-api-contract.mjs`: реальный Docker-стенд, все HTTP-сервисы,
  права, CRUD, optimistic lock, заметки, bulk, аудит, статистика и история сборок;
  собственные произведения удаляются, тестовые аккаунты отключаются.
- `scripts/verify-export-import.mjs`: консольный импортёр, все поля CSV,
  Excel для читателя и администратора, недоступность импорта через web.

Результаты сквозных проверок: `artifacts/api-contract-verification.json` и
`artifacts/export-import-verification.json`.

Полный Maven reactor: 27 тестов пройдено, 1 пропущен (локальный тест FFmpeg:
исполняемый файл отсутствует на Windows-хосте). Реальный FFmpeg в Docker отдельно
проверен сквозным сценарием `verify-web-stack.mjs`: загрузка и скачивание WAV,
публикация роли, MP3 в режимах SINGLE_FILE и BY_SEGMENTS, история и скачивание.
`verify-web-proxy.mjs` проверил cookies, одновременный refresh, CSRF, шесть OpenAPI
спецификаций, окончательное удаление, ограничение попыток входа и выход.
Дополнительно: 35 проверок контракта API, 7 клиентских тестов и Svelte-check без
ошибок и предупреждений. Все Maven-модули компилируются, включая прежние клиенты.
